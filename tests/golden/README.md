# Golden measurement tests

These tests simulate raw CSE7761 measurements and compare the calculated
V/I/P values with a reviewed reference file.

**Production rows cannot be captured manually while the load varies.** The
initial rows are a **baseline generated by the current code** from fixed raw
inputs and are marked `source=baseline`. They lock the current computed values.
Real production rows, if ever captured, use `source=prod`.

## Files

- `measurements.csv` — one row per input/output case.

## Manual approval rule

A result difference is **not** accepted automatically:

1. the test fails and prints the case, expected value and actual value;
2. the actual value must be checked against the production/reference measurement;
3. update the expected value **only** with `approved_by`, `approval_reason` and
   `captured_at` filled;
4. the change is reviewed in the pull request.

The test refuses rows with an empty `approved_by` or `approval_reason`. Updating
the reference file therefore requires an explicit human sign-off; do not
regenerate it blindly. A `source=baseline` row means "generated from the current
code for regression locking", not a physical measurement.

## Current baseline coverage

- 220 V and 240 V;
- 0, 0.1, 0.5, 1, 5, 10, 50 and 100 A;
- an export case with negative active power.

The values are generated by the **production offset pipeline** (the conversion
code unchanged from `main`), not by the new stock quadratic pipeline. The stock
quadratic model, range selection and parser are covered by separate unit tests.

The RMS current is unsigned: a 24-bit current with the MSB set is invalid and is
converted to zero. The import/export sign is carried by the 32-bit active power,
not by the current. The export golden case expects a negative power.

## Capturing a production row

Record, for a stable load:

- the raw registers `0x26` (voltage), `0x24` (current), `0x2C` (power);
- the chip coefficients `0x72`, `0x70`, `0x73`;
- the previous range flag and the calibration profile actually active;
- the expected stock outputs in mV/mA/mW (and the source/version).

Add the row to `measurements.csv` with `source=prod`, `captured_at` and
`approved_by`. If the expected value is not yet known, do not add a fake value;
keep the capture outside the golden file until it is verified.
